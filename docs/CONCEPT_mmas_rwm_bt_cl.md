## 一、要解決的問題：TSP（旅行推銷員問題）

一個業務員要拜訪 N 個城市，**每個城市剛好去一次**，最後回到出發點。城市間距離已知。問題是：

> 用什麼順序走，總路程最短？

聽起來單純，難在「順序的可能性多到爆炸」。10 個城市約 36 萬種走法，20 個城市超過 60 兆種，1000 個城市的可能性比宇宙原子還多。**沒有電腦能把所有走法試完。**

所以我們放棄「保證最短」，改成「用聰明的方法快速找到一條**夠好（接近最短）**的路線」。蟻群演算法就是這類「聰明猜」的方法。

---

## 二、靈感來源：真實螞蟻怎麼找到最短路

螞蟻沒有地圖、看不遠，卻能找到「蟻窩到食物」的近乎最短路徑，秘訣是**費洛蒙（pheromone，一種氣味）**：

1. 一開始螞蟻**亂走**，邊走邊留下費洛蒙。
2. 走**短路**的螞蟻來回比較快，**單位時間內在短路上累積的費洛蒙比較濃**。
3. 後來的螞蟻**傾向往費洛蒙濃的方向走**（但不是絕對，偶爾也亂走探索）。
4. 短路費洛蒙越濃 → 越多螞蟻走 → **正回饋**，最後集中到短路。
5. 費洛蒙會**隨時間揮發**，避免「先佔先贏」的爛路永遠主宰。

**核心觀念：費洛蒙是一種「群體記憶」。** 沒有單一螞蟻知道全貌，但整群透過塗改氣味，集體把「好路線的知識」累積下來。蟻群演算法（Ant Colony Optimization, ACO）就是把這機制搬到電腦上解 TSP。

---

## 三、把螞蟻搬到 TSP：一隻「電腦螞蟻」怎麼建一條路線

造一群虛擬螞蟻，**每隻獨立從某城市出發，一步步建出整條路線**：

- 站在目前城市，看「還沒去過的城市」，**用機率挑下一個**。
- 走過去，把它標記為「已拜訪」（避免重複）。
- 重複到所有城市都去過、回起點 → 一條完整路線，算出總長度。

「用機率挑下一個城市」的機率由兩個因素相乘決定每個候選的**吸引力**：

| 因素 | 符號 | 白話 | 直覺 |
|------|------|------|------|
| 費洛蒙 | τ (tau) | 過去經驗：這條邊好不好 | 好路線常走這條 → τ 高 → 吸引力高 |
| 啟發值 | η (eta) | 眼前直覺：城市近不近 = 1/距離 | 越近 η 越高 → 吸引力越高 |

每個候選城市的權重 = **τ^α · η^β**（α、β 是調整兩者重要性的指數；本專案預設 α=1、β=2）。然後**照權重比例抽籤**：權重大的較可能中，但不是一定——保留「探索」空間，偶爾走冷門才有機會發現更好的解。

> 一隻螞蟻的行為：**「大致往又近、又有好口碑的城市走，但帶點隨機性。」**

---

## 四、一輪「迭代」發生什麼事（預設每輪 100 隻螞蟻）

1. **所有螞蟻各建一條路線**（依上面的機率規則）。
2. **局部優化**：每條路線用「2-opt」稍微修短（見第六節）。
3. **找出這輪最好的路線**，更新「史上最佳」。
4. **費洛蒙揮發**：所有邊的費洛蒙打折（例如 ×0.9，揮發 10%）——「遺忘舊經驗」。
5. **費洛蒙沉積**：好路線經過的每條邊加費洛蒙（路線越短加越多）——「強化好經驗」。

進入下一輪，用更新後的費洛蒙再派 100 隻……重複幾百上千輪，費洛蒙慢慢「指向」好的邊，路線平均越來越短，最後收斂。

> **揮發 + 沉積是整個演算法的心臟**：一個負責遺忘、一個負責記憶，兩者拉鋸，讓群體既能利用已知好路（exploitation）又不會太早僵化、還能探索（exploration）。

---

## 五、MMAS（MAX-MIN Ant System）特別在哪

`mmas` 用的是改良版 MAX-MIN Ant System，加了三個防呆，專治「太快收斂卡住」：

1. **費洛蒙設上下限 `[τ_min, τ_max]`**（MAX-MIN 由來）：上限避免某條邊濃到「大家一定走它」而失去探索；下限保證冷門路永遠保有一點被選機會。
2. **只讓「最佳路線」留費洛蒙**：學習聚焦在「目前最值得參考的範本」。
3. **停滯就重置**：連續很多輪沒進步（卡住）時，把費洛蒙抹平重來，逼螞蟻重新大範圍探索。

---

## 六、為什麼還要「2-opt 局部搜尋」

螞蟻建的路線常「方向大致對，但有小瑕疵」——例如路線有兩段交叉打結，明顯繞遠。**2-opt** 是簡單修補：

> 找路線中兩條邊，把中間那段**反轉**接回去。若總長變短就採用。重複到沒得改。

直覺：**把打結、交叉的地方解開拉直**。螞蟻負責「大方向」，2-opt 負責「擦亮細節」。本專案**解的品質主要靠 2-opt 撐起**，關掉它（`--ls=0`）會明顯變差。

---

## 七、預設名字 `mmas_rwm_bt_cl` 的三個技術選擇

格式 `mmas_{選蟻方式}_{記錄已拜訪法}[_候選清單]`。這三個只影響「怎麼做得快、省記憶體」，不改變演算法在做什麼：

- **`rwm`（輪盤法 Roulette Wheel）**：把每個候選城市畫成輪盤上一塊扇形，**面積 = 它的權重（τ·η）**。轉盤射飛鏢，落在哪塊選哪個。權重大的扇形大、易中，但小扇形也有機會。就是「照比例隨機抽」最直觀的做法。
- **`bt`（位元遮罩 Bitmask）**：用一長串開關記哪些城市去過（每城市 1 bit，0=沒去、1=去過）。查詢超快、最省記憶體。
- **`cl`（候選清單 Candidate List）**：最重要的加速。好路線幾乎只連「附近城市」，所以**事先幫每個城市算好最近的 32 個鄰居**，螞蟻每步只在這 32 個裡挑。城市很多時，從「每步看上千個」變「每步看 32 個」→ 快非常多；萬一這 32 個都去過了才退而看全部剩下的。額外好處：不必存「每對城市的完整 N×N 權重大表」（城市一多就塞爆顯卡記憶體），只存「每城市 × 32 鄰居」的小表 → 大問題才跑得動。

> 一句話：**「用輪盤照吸引力抽下一城（rwm）、用位元開關快速記去過哪（bt）、每步只考慮最近 32 個鄰居（cl）。」** 靈魂仍是 MMAS。

---

## 八、為什麼用 GPU

那 100 隻螞蟻彼此獨立、**可以同時走**。GPU 擅長「同一件事大量平行做」：

- 100 條路線同時建構。
- `cl` 模式下更妙：候選剛好 32 個，GPU 執行緒以 32 個為一組（一個 warp），於是**一個執行緒負責一個候選城市**，32 個同時算完同時抽 → 榨乾硬體。
- 揮發、沉積、2-opt 也都能大量平行。

整個專案的意義就是：**把本質上很平行的 MMAS，重寫成 GPU 上高效執行的版本。**

---

## 九、串起來（一句話版）

> 派 100 隻螞蟻，每隻**只看最近 32 個鄰居、照「近 + 費洛蒙濃」的吸引力用輪盤抽路**，建出 100 條路線 → 用 2-opt 拉直 → 挑最好的 → 全體費洛蒙**揮發一點（遺忘）**、在最佳路線上**加費洛蒙（記憶）**，夾在安全上下限內、卡住就重置 → 重複上千輪，路線越來越短，最後輸出史上最佳。

---

# 十、5 個城市手算範例（一步步算給你看）

下面用 **5 個城市**完整手算一輪，把上面的抽象變具體。

> ⚠️ 兩個為了好懂的縮小：
> 1. 真實預設候選清單是 **32 個**鄰居，但這裡只有 5 個城市，所以示範改成**每城市記 2 個最近鄰**。
> 2. MMAS 的 τ_min/τ_max 上下限公式較複雜，這裡**初始費洛蒙一律設 τ=1**、暫不套用夾限，只示範「揮發/沉積」的機制。原理完全相同。
>
> 其餘忠於預設：α=1、β=2（吸引力 = τ · (1/距離²)）、揮發率 10%（每輪 ×0.9）。

## 10.1 城市座標與距離

5 個城市座標（單位格）：

```
   y
 6 |        E(2,6)
   |
 3 | D(0,3)      C(4,3)
   |
 0 | A(0,0)      B(4,0)
   +---------------------- x
     0    2    4
```

兩兩直線距離（四捨五入到整數，TSPLIB EUC_2D 規則）：

| | A | B | C | D | E |
|---|---|---|---|---|---|
| **A** | – | 4 | 5 | 3 | 6 |
| **B** | 4 | – | 3 | 5 | 6 |
| **C** | 5 | 3 | – | 4 | 4 |
| **D** | 3 | 5 | 4 | – | 4 |
| **E** | 6 | 6 | 4 | 4 | – |

## 10.2 事先算好「每城市的 2 個最近鄰」（候選清單，cl）

對每個城市，挑距離最小的兩個：

| 城市 | 各鄰距離 | 最近 2 個（候選清單） |
|------|----------|----------------------|
| A | D3, B4, C5, E6 | **[D, B]** |
| B | C3, A4, D5, E6 | **[C, A]** |
| C | B3, D4, E4, A5 | **[B, D]** |
| D | A3, C4, E4, B5 | **[A, C]** |
| E | C4, D4, A6, B6 | **[C, D]** |

這就是 `cl` 預先建好的表。之後螞蟻每一步**只看自己候選清單裡的城市**。

## 10.3 初始費洛蒙

所有邊 **τ = 1**（均勻，代表「還沒有任何經驗」）。

## 10.4 派一隻螞蟻建路線（rwm 輪盤 + bt 位元遮罩 + cl 候選清單）

**起點隨機**，假設抽到 **A**。
已拜訪用 5 個 bit 記錄（順序 A B C D E）。出發：`已拜訪 = [1,0,0,0,0]`（只有 A 是 1）。

---

### 第 1 步：目前在 A

- A 的候選清單 = [D, B]，查 bit：D、B 都還沒去 → 兩個都是有效候選。
- 算吸引力 `權重 = τ · (1/距離²)`：
  - 到 D：`1 · 1/3² = 1/9 ≈ 0.1111`
  - 到 B：`1 · 1/4² = 1/16 = 0.0625`
- 總和 = 0.1111 + 0.0625 = 0.1736
- 轉成機率（輪盤的扇形大小）：
  - **D：0.1111 / 0.1736 ≈ 64%**
  - **B：0.0625 / 0.1736 ≈ 36%**
- 輪盤射飛鏢：把 [0,1) 切成 `D = [0, 0.64)`、`B = [0.64, 1)`。
  假設亂數 `r = 0.50` → 落在 D 區間 → **選 D**。

> 注意：B 比較遠（距離 4 vs 3），又因 β=2 把「近」放大，所以 D 的扇形明顯大。但 B 仍有 36% 機會——這就是「帶隨機性的探索」。

走到 D。`已拜訪 = [1,0,0,1,0]`（A、D）。

---

### 第 2 步：目前在 D

- D 的候選清單 = [A, C]，查 bit：A 已去（跳過），C 還沒 → 只剩 C。
- 唯一候選 → **選 C**（機率 100%）。

走到 C。`已拜訪 = [1,0,1,1,0]`（A、C、D）。

---

### 第 3 步：目前在 C

- C 的候選清單 = [B, D]，查 bit：D 已去，B 還沒 → 只剩 B。
- 唯一候選 → **選 B**。

走到 B。`已拜訪 = [1,1,1,1,0]`（A、B、C、D）。

---

### 第 4 步：目前在 B（觸發「回退」）

- B 的候選清單 = [C, A]，查 bit：**C、A 都去過了！** 候選清單全滅。
- → **回退機制**：改看「所有還沒去的城市」= 只剩 **E**。
  （一般情況會在剩下的城市裡挑 τ·η 最大者；這裡只剩 E。）
- **選 E**。

走到 E。`已拜訪 = [1,1,1,1,1]`，全部去過。

---

### 收尾：回起點 A

路線：**A → D → C → B → E → A**
長度 = AD3 + DC4 + CB3 + BE6 + EA6 = **22**

## 10.5 2-opt 把它拉直

把這條路畫出來會發現 **B→E 和 D→C 兩條線交叉打結**（B(4,0)→E(2,6) 會穿過 D(0,3)→C(4,3)）：

```
   E
  /|\
 / | \        ← B→E 斜線穿過 D—C 橫線（交叉！）
D--+--C
|     |
A     B
```

2-opt 解結（反轉中間一段）：

- **第 1 次**：反轉讓路線變 `A → B → C → D → E → A`，長度 = 4+3+4+4+6 = **21**（22→21）。
- **第 2 次**：再反轉 D、E 一段，變 `A → B → C → E → D → A`，長度 = 4+3+4+4+3 = **18**（21→18）。

得到 **18**，正是這 5 個城市的最短路線（沿著外圍走一圈，沒有任何交叉）。這隻螞蟻的路線就從 22 被 2-opt 修到 18。

## 10.6 更新費洛蒙

這輪最佳路線 = `A-B-C-E-D-A`，成本 18。

**① 揮發**（所有邊 ×0.9）：每條邊的 τ 從 1 → **0.9**。

**② 沉積**（只加在最佳路線經過的邊，加 `Δτ = 1/成本 = 1/18 ≈ 0.0556`）：

最佳路線的 5 條邊：A-B、B-C、C-E、E-D、D-A，各 τ = 0.9 + 0.0556 = **0.9556**
其他所有邊：維持 **0.9**

| 邊 | 在最佳路線上？ | 新 τ |
|----|:---:|------|
| A-B, B-C, C-E, E-D, D-A | ✅ | **0.9556** |
| A-C, A-E, B-D, B-E, C-D | ❌ | 0.9 |

**這就是「群體記憶」生效的瞬間**：好路線上的邊現在費洛蒙略高，下一輪螞蟻會稍微更偏向走它們。

## 10.7 第二輪：費洛蒙開始發揮作用

第二輪同樣假設螞蟻從 A 出發，看候選清單 [D, B]：

- 到 D：邊 D-A **在最佳路線上** → τ=0.9556 → 權重 `0.9556 · 1/9 ≈ 0.1062`
- 到 B：邊 A-B **也在最佳路線上** → τ=0.9556 → 權重 `0.9556 · 1/16 ≈ 0.0597`

（此例 A 的兩個候選剛好都被強化，所以比例變化不大；但**沒被強化的邊**會相對越來越弱。）

關鍵體會：**單一輪的費洛蒙變化很小、距離 η 在初期主導**；但好邊每輪被反覆加強、爛邊每輪揮發掉，**上千輪累積下來，費洛蒙的差距會放大成決定性的引導**，把整群螞蟻推向好解。這正是蟻群演算法「慢慢學會」的過程。

## 十一、用這個小例子回看三個技術選擇

- **rwm**：第 1 步「64% 對 36% 的輪盤抽 D」就是它。
- **bt**：每步用那串 `[1,0,1,1,0]` 開關 O(1) 查「去過沒」，第 4 步靠它瞬間發現候選全滅而回退。
- **cl**：每步只看 2 個（真實是 32 個）鄰居，不必掃全部城市——第 4 步候選清單全滅時才退去看「所有未拜訪」。

把城市數從 5 換成 1000、候選從 2 換成 32、螞蟻從 1 隻換成 100 隻同時在 GPU 上跑、迭代上千輪，就是 `mmas_rwm_bt_cl` 實際在做的事。

## 12.1 四個 n×n 矩陣各存什麼（用 5 城市對應）

四個都是 **n×n 的 float 表格**，row-major（列優先）：第 `i` 列第 `j` 行 = `矩陣[i*n + j]`，
代表「城市 i → 城市 j 這條邊」的某個值。以 5 城市（A=0,B=1,C=2,D=3,E=4）展開：

### ① `d_dist_matrix[i*n+j]` = 距離（常數，整個 run 不變）
2-opt 與算路徑長度用。
```
     A  B  C  D  E
A    0  4  5  3  6
B    4  0  3  5  6
C    5  3  0  4  4
D    3  5  4  0  4
E    6  6  4  4  0
```

### ② `d_heuristic[i*n+j]` = η = 1/距離^β（β=2，常數，不變）
「眼前直覺：越近越香」。
```
     A      B      C      D      E
A    –      .0625  .0400  .1111  .0278
B    .0625  –      .1111  .0400  .0278
C    .0400  .1111  –      .0625  .0625
D    .1111  .0400  .0625  –      .0625
E    .0278  .0278  .0625  .0625  –
```
（η(A,D)=1/3²=.1111、η(A,B)=1/4²=.0625，正是第十節手算的數字。）

### ③ `d_pheromone[i*n+j]` = τ = 費洛蒙（會變，每輪揮發/沉積）
「群體記憶」。第一輪初值全 1；跑完一輪（最佳路線 A-B-C-E-D-A，成本 18）後，

## 12.2 2-opt 實際怎麼翻轉路線

路線用兩個陣列：`route[]`（城市順序）+ `pos_in_route[city]`（反查：某城市在第幾位）。
一次 2-opt = **反轉 `route` 的一個區間 `[beg,end)`**（`reverse_route_segment`，`src/mmas.cu:2086`）。

範例（起始 `route=[A,D,C,B,E]`，長度 22）：

**第 1 次**：反轉位置 `[1,4)`（D,C,B）
```
位置: 0  1  2  3  4
前:   A [D  C  B] E
後:   A [B  C  D] E
```
移除邊 A-D(3)、B-E(6)，接上 A-B(4)、D-E(4) → 22→**21**。

**第 2 次**：在 `[A,B,C,D,E]` 反轉位置 `[3,5)`（D,E）
```
位置: 0  1  2  3  4
前:   A  B  C [D  E]
後:   A  B  C [E  D]
```
移除邊 C-D(4)、E-A(6)，接上 C-E(4)、D-A(3) → 21→**18**（最佳）。

**為什麼能平行又不翻太多**：對稱 TSP 裡「反轉區間」和「反轉它的補集」是同一個環（只是方向相反），
所以 `src/mmas.cu:2101` 的 `if (3*len <= 2*dimension)` 挑**較短那半**翻，最多動一半元素。
翻轉本身由 block 內所有 thread 同時做：lane k 交換 `route[beg+k] ↔ route[end-1-k]`，
一步並行換多對，並同步更新 `pos_in_route`；翻完把 4 個受影響端點的 don't-look bit 清 0 再查。

## 12.3 100 隻螞蟻的並行度在哪？（與 latency bound 的關係）

先分清楚三層並行——這正是 OOM 報告「方向 2」的核心：

| 層級 | 在本程式裡是什麼 | 規模 |
|------|------------------|------|
| **Block 級（跨 SM）** | **100 隻螞蟻 = 100 個 block**，分散到 V100 的 80 個 SM 同時跑 | 100 |
| **Warp / SIMT（warp 內 32 lane 齊步）** | 一隻螞蟻 = 1 warp，**32 lane 各管候選清單一格** | 每螞蟻 32 |
| **ILP（單 thread 指令串內重疊）** | 單 lane 內互不相依的算術（展開的 `dist^β` 連乘、scan） | 很少 |

→ **「100 隻螞蟻平行」其實是 Block 級並行（thread-block / TLP），不是 ILP。**
ILP 指「單一執行緒指令流裡互不相依的指令在 pipeline 重疊」，本程式很少 —— 這也是它 latency bound 的原因之一。

**最關鍵的現實（ncu 數據）**：
- Grid=(100,1,1)、Block=(32,1,1) → 全 GPU 只有 **100 個 warp 在飛**。
- V100 可容納 ≈ 80 SM × 64 warp ≈ **5120 warp** → **occupancy 僅 1.95%**。
- 後果：warp 太少，某 warp 卡在長延遲指令（`sqrt`、分散的 `pheromone[node]` 讀取）時
  **沒有別的 warp 填空檔** → GPU 大量閒置 → **latency bound**。

**「是不是只有建路線 + 局部優化」**：是，這兩支是兩個主要的 100-block 平行階段
（build kernel 佔 ~97% GPU 時間）；其餘每輪 kernel 也平行，只是規模不同：
```
build_ant_sol   <<<100, 32>>>            一 block 一螞蟻（主角，97%）
two_opt_nn      <<<100, ls_warps×32>>>   一 block 一螞蟻的路線
cand cache 更新 <<<n,   128>>>           一 block 一城市
evaporate       <<<n,   256>>>           一 block 一城市（一列費洛蒙）
deposit         <<<1,   256>>>           單 block（只改最佳路線的邊）
update_best     <<<1,   32>>>            單 block（找最小成本）
```

**但 100 隻螞蟻提供的平行度「太少」、撐不滿 GPU**，這就是未完成的「方向 2（治本）」：
**每隻螞蟻多給幾個 warp**，或**一個 block 塞多隻螞蟻**，把在飛 warp 數從 100 拉到足以蓋住延遲。
砍 FP64 pow（方向 1）只降單顆指令延遲、治標；真正天花板是「平行度不足 + memory latency」。
